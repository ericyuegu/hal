# Conditioned self-play evaluation

Run an O65 actor against frozen anchors with `scripts.eval_o65`. The evaluator
batches players and matches by actor weights in MSL or Dolphin. Each player
receives lambda, delay, replan interval and identity at u=0.95. An action chosen
at frame t first executes at t+D+1. We re-encode context through a second cache
for each 128-frame block.

For the proxy pilot, use the frozen final grid and evaluate once in MSL:

```sh
PYTHONPATH="$HOME/src/melee-sim-light:$PWD" uv run python -m scripts.eval_o65 \
  --checkpoint runs/train/checkpoints/update-00002000.json \
  --anchors runs/proxy/final.pt --output runs/held-out \
  --data-dir "$HOME/src/melee-sim-light/data" \
  --protocol experiments/o65/pilot-evaluation.json --split held_out \
  --lambda-grid 1 --cadence-grid 8/4 --simulators msl
```

Use [the pilot protocol](../../experiments/o65/pilot-protocol.md) to interpret
results and [the native instructions](../sim/NATIVE.md) to build the adapter.
For separate simulator comparisons, select both backends with
`--simulators msl dolphin --compare-events`. Use distinct policy behavior:
critic-only changes or lambda changes at BC initialization leave actor behavior
unchanged. Dolphin may need Xvfb. `--dolphin-workers` limits its concurrent
matches; MSL runs a cell's schedule together.

## Matches and outcomes

The reader accepts `hal.o65.protocol.v2`: held_out and max_frames. Within
held_out, supply seeds and starts, with name, stage and characters per start.
The evaluator runs each seed/start under both port orientations, at four
stocks and zero damage. Policy draws use independent logical-player counters,
with the same draws after a port swap or simulator change.

The final pilot uses (D=8,R=4) across 32 matchups, six stages and both
orientations, for 384 matches. Each game continues to a stockout or the
eight-minute timeout.

MSL controller readback passes through native_controller_readback before
feature construction, while delayed queues retain submitted actions. Dolphin
cannot accept injected game RNG through the Session API, so we record its
observed initial RNG and compare event statistics under matched policy draws.

Before held-out play, the evaluator creates a claim in the output's parent
directory. Preserve this claim after failure and use a shared parent for final
results. The evaluator writes protocol.json before play, match files after
each cell, then results.json by atomic rename after completing the schedule.
It reports emulator failure as an evaluation failure.

Results use `hal.o65.evaluation-results.v2`. We divide each batch's elapsed
time equally among its matches so summed wall_seconds measures runtime.
We calculate intervals over paired seed/start units. Net stocks/min averages
paired rates. net_stock_lcb uses a one-sided 95% normal lower bound. Win rate
scores completed stockouts, with timeouts and frame-budget stops reported
separately. Fewer than two pairs produces null interval bounds.

Event rates count active frames from frame 0 and onsets of death, ledge grabs
or techs. We classify blast-zone death animations and report a zero-damage
self-destruct proxy. Native observations contain no KO-credit field.
The default frame budget includes 123 countdown frames and the timeout frame
at 28,800.

## Actor loading

Training format v7 manifests refer to complete training state, native snapshots
and evaluation format v3 actors. The loader verifies the manifest and actor
before loading weights. Training restore also compares the exported actor with
the training state. Actor files store architecture, conditioning ranges,
weights, feature statistics, decoder precision and source/input records.

When loading O63 percentile format v5, we read architecture and training-source
statistics, then add zero conditioner columns and a zero-initialized critic
residual. The committed pilot input manifest records the selected checkpoint.
We reject other checkpoint schemas and non-finite weights or statistics.

The decoder defaults to BF16 projections and attention with FP32 parameters.
Norms, conditioning, bias addition, probability arithmetic, sampling thresholds
and critic heads use FP32. Evaluation reads saved decoder precision and rejects
a conflicting override. O63 BC files permit an explicit FP32 control.

For cache and queue parity tests, `--execution serial` runs independent players.
Serial evaluation also supports a sliding-context comparison. Batched evaluation
uses block restart. Deployment still requires separate latency measurements.
