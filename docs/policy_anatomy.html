Anatomy of a Melee Policy

A 15-million-parameter Transformer reads two seconds of Super Smash Bros. Melee and writes the next controller frames. Every part of it is the residue of an experiment that we ran and scored in a live game.

15,053,039 parameters 128 frames of context 10 predicted offsets 60 Hz closed loop ~40 scored experiments

One number decides everything: net stocks per minute. We play the model against the in-game CPU and count the stocks it takes minus the stocks it loses, per active minute. The LCB beside each score is the conservative one-sided 95 % lower bound of that difference.

Validation loss does not decide anything. Experiment 028 reached a lower final loss than the model it replaced, after twice the data, and played worse: NLL 1.1444 against 1.1596, but −0.23 stocks per minute against +0.03. Since then, only closed-loop play ranks a model.

KEY

A short glossary

The words this page uses, and the distinctions that get blurred most often. Hover a term to light up the part of the picture it names.

Timing and control

Frame16.7 ms
Melee runs at 60 Hz. Every count on this page is in frames, not seconds.
Action chunkH · chunk length · planning horizon
The block of future actions that one forward pass produces. Those three names all mean the same number.
Replan intervalR · replanning frequency
Game frames between forward passes. R = 1 runs the model every frame. Not the same as H. H is how much you compute. R is how often you compute it. H ≥ R, and the unused tail is thrown away.
Prediction delayd · reaction delay
Frames between the newest observation and the first action that executes. It is a training choice as well: the model learns to predict for frame t+d.
Inference latency
Wall-clock time for one forward pass, in milliseconds. Not the same as delay. Latency is milliseconds, and the hardware and model size set it. Delay is frames, and the schedule sets it. Latency forces delay up only when a pass cannot finish inside d frames.
Receding horizon
Compute a chunk, execute part of it, discard the rest, compute again. The standard control loop, and the reason R < H is useful.
Open loopvs closed loop
Acting without new observations. A chunk executed with R = H is open loop for H − 1 frames. Closed loop means the model sees the result of its last action before it picks the next.

Autoregressive conditioning — three separate axes

"Autoregressive" only says that things are produced in an order, each conditioned on what came before. This model has three different orders in it, and each one is an independent choice.

Causal attentionacross time
Each frame's state reads only earlier frames. The ordinary language-model axis, and it is always on here.
Autoregressive chunkacross the chunk · future conditioning
Each predicted future frame conditions on the frame the model predicted before it.
Independent heads
The alternative: one output head per future offset, all reading the same trunk state and none reading each other. Cheaper, and unable to represent any correlation between future frames.
Within-frame factorizationgroup conditioning
One controller frame is four values. Choosing them in a fixed order, each conditioned on the ones already chosen, models their joint distribution. The alternative treats the four as independent given the state.
FiLMfeature-wise linear modulation
Scale and shift a hidden state using a conditioning input. It is how each chosen group reaches the next one.
Teacher forcing
In training, condition each step on the true previous value, so every step runs in one parallel pass.
Exposure bias
At play time the model conditions on its own samples, which it never saw in training. This is the price of teacher forcing, and it grows with chunk length.
Ancestral sampling
Draw the first group, feed it back in, draw the second, and so on. What the model does at play time.
KV cache
Keep the attention keys and values from earlier steps, so each new step costs one token of work instead of a full re-run.
Multi-token prediction
Train one model to predict several future steps, not only the next one. Offsets that never execute still shape the trunk.

What goes in, what comes out

Input encodingfeaturization
How the past is presented to the model. Here the previous controller frame becomes a learned class embedding plus a linear map of its physical stick and trigger values.
Output parameterizationthe head
What the model predicts. Here: four categorical distributions over controller classes. Separate from input encoding, even though the two share a class set. Experiment 028 changed only the input. The codec change in section 05 changed only the class set.
Quantizationdiscretization
Map a continuous value to the nearest point of a fixed set. The main stick is quantized to 37 positions.
Class setcodebook · vocabulary
The fixed set of points. Changing it changes what the model can express, and how many training examples each class receives.
Codec
The pair of maps: raw frame → class ids, and class ids → raw frame. One object, shared by the input encoder, the decoder and the sampler.
Logit maskingconstrained decoding
Set impossible classes to minus infinity before sampling, so an illegal combination has probability zero.
Conditioning
Anything fed to the model that it does not predict: the two characters, the stage, which offset a step is for, and the controller groups already chosen.

Training objectives

Behaviour cloningBC
Supervised learning from human play: raise the likelihood of the action the player actually took.
Advantage-weighted regressionAWR
Behaviour cloning with each example weighted by how good its outcome was.
Offline reinforcement learningIQL
Learn a value or Q function from a fixed dataset and use it to improve the policy, without playing. IQL is one method for it.
Auxiliary loss
A second training signal on a head that is discarded at play time. Its job is to shape the shared trunk.

Measurement

Validation NLL
Negative log-likelihood on held-out replays. It measures fit to human data, and on this page it ranks nothing.
Net stocks per minute
Stocks taken minus stocks lost, per active minute, against the in-game CPU. The score on this page.
Lower confidence boundLCB
A conservative one-sided 95 % bound on that score, so a lucky sample cannot read as a win.
Control
What a comparison holds fixed. A weak control tells you that something changed, not what.
Paired evaluation
Both models play the same matchups, in the same order, with the same seed, so the difference is not schedule luck.
Iso-FLOP
Compare models at equal training compute, rather than at equal parameters or equal data.
Positions · examples · updates
Positions are the frames the optimizer processed, examples are sequences, updates are optimizer steps. Batch × updates = examples; examples × context length = positions.

01

Observation encoder

Turn one frame of Melee into one token.

Each frame gives the model four player blocks, four item slots, the match conditioning, and the ego player's own previous controller frame. A linear projection joins them into a single 384-dimension token. The encoder holds 185,388 parameters, about 1.2 % of the model.

Two rules shape this stage. First, every float carries a validity mask, so a missing value is explicit and never a magic number. Second, the model never reads the opponent's controller inputs. It must infer the opponent's intent from gamestate alone, because at play time no such input exists.

The previous action does not enter as a one-hot code. It enters through the same codec that the output head uses: a learned class embedding plus a linear map of the physical stick and trigger values. One table serves both directions.

02

Transformer trunk

Eight causal blocks over 128 frames. Ninety-four percent of the parameters.

The trunk is a plain pre-norm stack: rotary positions, causal attention, RMS normalization without affine weights, and no bias anywhere. It holds 14,155,776 of the model's 15,053,039 parameters, 1,769,472 per block. A 128-frame window is about 2.1 seconds of play.

The attention mask obeys three rules together. A query must not read the future. A query must not read its own sample's cold-start padding. The diagonal always stays open, because a fully masked row makes the attention output undefined.

Capacity is the least settled part of the whole model. Experiment 039 trained seven sizes, from 7.0M to 293M parameters, at five data budgets, and then played every checkpoint against the CPU at nine control settings. That is 291 evaluated cells, 96 boots each, on one RTX 3060. The explorer below holds all of them.

The scaling story falls apart under it. No column of the grid is monotonic in model size. No line separates cleanly with more data. And validation loss — which does improve smoothly with both size and data — is anti-correlated with play across the whole grid.

The current 128-frame context has no matched larger partner. Treat it as untested.

03

Temporal action decoder

Ten future offsets, decoded in a chain.

Each trunk state feeds a small causal decoder of two blocks at d128. The decoder emits ten offsets: 1, 2, 3, 4, 5, 6, 9, 12, 16 and 20 frames ahead. Every step reads the action the previous step chose, plus an embedding of its own offset. In training all ten steps run in one teacher-forced pass. At play time the same blocks run one step at a time from a key-value cache.

Only the dense 1 to 6 prefix ever reaches the emulator. The sparse tail exists to shape the trunk. It is a training signal, not a plan.

Experiment 037 is the cleanest test in the whole programme. It fixed one model, one dataset, one parameter count and one optimizer, then switched two information paths on and off. The panels below split that matrix so each one shows a single effect.

Experiment 037, four cells of one 2×2, same checkpoint per cell, 96 boots per point. The ranking reverses with the horizon: at one executed frame the cell with group conditioning alone is best, at four and six the cell with both paths is best.

04

Within-frame group chain

Four controller groups, chosen in order, each one conditioning the next.

A controller frame is not one decision. It is four: the C-stick, the main stick, the shoulder value and the buttons. The model picks them in that fixed order. After each pick, a small projection of the groups already chosen scales and shifts the decoder state for the next group. A separate linear read of the trunk state adds to every group's logits, so the head never has to relearn what the trunk already knows.

One hard constraint stays outside the network. A digital shoulder click implies full analog pressure, so button classes that contradict the sampled shoulder value are masked to minus infinity before sampling.

Group-chain evidence
ChangeFrom → toΔ scoreΔ LCBControl

Verdict: order the four groups and let each one see the last. The gain is +0.24, and experiment 037 factorizes it exactly: the effect holds whether or not future conditioning is present.

What this does not show. Only one group order was ever tested against a proper control. Head capacity gave +0.11 for 12.6 % more parameters, and a later head-to-head did not confirm it.

05

Controller codec

The one boundary between raw values and classes. The largest single recovery in the programme.

The codec quantizes a controller frame into four class indices and turns four indices back into a controller frame. The current recipe restores a historical class set: 6 button classes, 37 main-stick classes, 9 C-stick classes, and 5 fused shoulder levels. The model keeps its modern, larger output tensors; the codec simply masks the classes it does not use. No trainable tensor changed.

The historical codec also restores an early-release reducer. The reducer compares each raw button set with the set before it. It emits the lowest-index button that is newly pressed. If buttons were released and nothing new was pressed, it emits None. An unchanged set repeats the previous output.

06

Closed-loop timing

Three integers, no parameters, and the second-largest effect we measured.

A plan is not a policy. Three numbers decide how a plan meets a 60 Hz game:

  • Prediction delay d — frames from the newest observation to the first predicted action.
  • Plan length H — actions generated in one plan.
  • Replan interval R — game frames between inference requests.

A plan covers frames [t+d, t+d+H). The scheduler anchors each plan to the observation it came from and releases a frame only when that frame arrives. The newest eligible plan wins. The current recipe runs d = H = R = 1: observe, decide, act, repeat.

Timing evidence
ChangeFrom → toΔ scoreΔ LCBControl

Verdict: latency is expensive. Moving the prediction delay from 1 frame to 12 costs −1.11 stocks per minute — larger than any architecture change on this page except the codec. Twelve frames is 200 milliseconds, and the model has no way to buy that back.

What this does not show. Replan interval alone has never been measured. Every test so far moved it together with plan length or with delay. That is an evaluation-only experiment on one existing checkpoint, and it is the cheapest open question on this page.

07

Training recipe

Where the data comes from, and how the optimizer sees it.

The model trains on anonymized ranked Melee replays, materialized to a versioned columnar schema. A reservoir sampler draws four windows per replay. Each step processes 512 sequences of 128 frames, about 65,500 positions. Muon updates the trunk blocks; AdamW updates everything else. The learning rate warms up for 500 steps and then follows a cosine to a floor. Half the action loss sits on the next frame; the other nine offsets share the rest.

Recipe evidence
ChangeFrom → toΔ scoreΔ LCBControl

Verdict: the sampler and the batch size are worth as much as most architecture work. One window per replay beat four by +0.73. A batch of 128 beat 2,048 by +0.47 at identical data. Both are free.

What this does not show. The window result comes from an older sampler. The current reservoir sampler has never been tested at one window per replay, and that repeat is the second open question on this page.

And one negative result worth keeping. Swapping AdamW for Muon plus AdamW moved the score by +0.03. Optimizer and learning rates changed together. There is no evidence here for a large Muon benefit.

09

What we still cannot claim

Eight questions the current evidence does not answer, in the order we would run them.

1

Professional data against ranked-anonymous data

The old champion trained on one professional player's replays. Existing comparisons hint at a 0.4 to 0.5 effect, but none holds the current recipe fixed.

Train both corpora with identical samples, updates, seed, sampler, codec and losses. Evaluate on the same paired schedules.

2

Windows per replay, on the current sampler

One window per replay beat four by +0.73 — on a sampler we no longer use.

Run the current recipe at one and four windows, reservoir 4,096 in both arms, sampled frames and updates held fixed.

3

Replan interval, on its own

Every horizon test so far tied the replan interval to plan length or to delay. A flow checkpoint moved +0.02 between two settings that changed both.

One checkpoint, delay fixed at 1, decode 6 frames every time, evaluate R = 1, 2, 3, 6 with paired randomness. No training needed.

4

Which target horizon the loss should cover

Adding a third target offset cost −0.20, but the target count and the next-frame weight moved together.

Three arms: next frame only; the legacy pair at half and half; the current ten offsets with the next frame fixed at half. Hold total loss weight, data and parameters fixed.

5

Context length

There has never been a sweep. The three observations we have each change compute, attention and protocol at the same time.

Evaluate 128, 256, 512 and 1,024 frames with local attention width 128, batch × context fixed, updates fixed, and the same replay end frames.

6

Which quarter of the codec change helped

The +0.75 recovery bundles four changes.

A 2×2 first: modern against legacy output classes, crossed with the reducer off and on, at d = H = R = 1 and half the loss on the next frame. Then test timing and loss allocation separately.

7

Model size, on the recovered recipe

The capacity result comes from the previous recipe and reverses with control timing. It does not establish a general size effect.

Rerun the existing four-point capacity matrix — 2.506M, 4.722M, 9.445M and 15.053M at matched compute.

8

The architecture package, on its own

The architecture change cost −0.66, but the loader and the sampler changed with it.

Hold the current data, codec, loss and timing, and change only the architecture package. If it matters, split it into trunk, temporal decoder, skip connection and output head.

The model is what survived. Seven of these eight questions are cheap, and one of them needs no training at all.
